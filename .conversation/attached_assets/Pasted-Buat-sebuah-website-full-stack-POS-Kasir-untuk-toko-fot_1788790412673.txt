Buat sebuah website full-stack POS/Kasir untuk toko fotokopi, print, finishing, dan ATK.

Nama aplikasi: Potocopy QTA

Tujuan utama aplikasi:
Membuat sistem kasir yang cepat digunakan di meja kasir, tetapi sekaligus memberikan transparansi penuh kepada pemilik toko mengenai seluruh transaksi, omzet, pembayaran, stok, aktivitas kasir, pembatalan transaksi, dan laporan harian.

Jangan membuat desain POS generik. Aplikasi harus terasa seperti produk SaaS/POS profesional yang benar-benar dibuat khusus untuk usaha fotokopi.

1. PRINSIP PRODUK

Prioritas utama:

1. Kasir dapat membuat transaksi secepat mungkin.
2. Pemilik dapat mengetahui seluruh aktivitas toko.
3. Tidak ada transaksi penting yang dapat hilang tanpa jejak.
4. Stok dan penggunaan bahan dapat dilacak.
5. Interface harus sangat mudah dipahami pengguna non-teknis.
6. Desktop/tablet menjadi prioritas untuk kasir, tetapi dashboard owner harus nyaman digunakan dari HP.
7. Semua data transaksi harus persistent di database.
8. Jangan menggunakan mock data setelah backend/database selesai.
9. Jangan membuat fitur palsu yang hanya bekerja di frontend.
10. Semua operasi penting harus memiliki validasi server-side.

15. SHIFT / KAS KASIR

Jika memungkinkan, implementasikan shift kasir.

Kasir:
OPEN SHIFT

Masukkan modal awal.

Selama shift:

- Penjualan cash
- QRIS
- Transfer

Ketika selesai:
CLOSE SHIFT

Sistem menghitung:

Modal awal

+ penjualan cash

- refund/pengeluaran cash
  = expected cash

Kemudian kasir memasukkan uang fisik:

Actual cash

Sistem menunjukkan:

Expected: Rp500.000
Actual: Rp495.000
Selisih: -Rp5.000

Owner dapat melihat laporan shift.

27. DEFINITION OF DONE

Aplikasi dianggap selesai jika alur berikut benar-benar bekerja:

Kasir login
→ buka shift
→ pilih Fotokopi A4
→ masukkan 2 lembar
→ checkout
→ pilih Cash
→ masukkan pembayaran
→ sistem menghitung kembalian
→ transaksi tersimpan database
→ stok/bahan terkait berkurang jika recipe aktif
→ receipt dapat dicetak
→ transaksi muncul di riwayat
→ omzet dashboard owner bertambah
→ audit log mencatat transaksi
→ owner dapat melihat detail transaksi
→ owner dapat melihat transaksi berdasarkan tanggal/kasir
→ owner dapat melihat laporan
→ owner dapat melihat stok
→ kasir tidak dapat mengakses fungsi owner.

Jika salah transaksi:

Kasir/owner
→ cancel transaction
→ wajib memasukkan alasan
→ transaksi tidak dihapus
→ stok dikembalikan sesuai aturan
→ audit log dibuat
→ dashboard/laporan menghitung status transaksi dengan benar.
